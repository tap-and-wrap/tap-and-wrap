# Owner Dashboard V2

## Approved design and implementation plan

The owner's attached 6 November 2026 brief is the approved specification. Preserve the existing JavaScript applications, session providers, commerce workflows, brand tokens, original logo and customer builders. No persistent database mutation, configuration publication or pricing change is part of this redesign.

Use one compact, role-aware header with exactly Products, Categories, Orders, Customization, Discounts, Payment, Customers and Analytics. The logo opens the dashboard; the Home action opens the storefront. Customization offers only Gift Box and Standalone Engraving. Mobile uses the existing modal-dialog lifecycle. Remove the promotional header, storefront footer and repeated admin menu from the admin workspace.

The dashboard combines period-labelled recorded collections, order counts, recent orders and the existing operational attention queue. Analytics must distinguish actual ledger collections from legacy paid snapshots and must never count unpaid service requests as revenue. Unified Orders retains existing authoritative order details and service payment gates. Gift Box management embeds the working revision-aware editors under contextual tabs. Old bookmarks redirect to their approved workspaces; historical requests remain contextual within Orders.

Retire bundle and customer-review writes at the API boundary and service entry points while retaining historical models and snapshots. Remove public bundle presentation. Fixed approved homepage testimonials remain unchanged. Runtime promotion calculations use discount codes only after an authorized read-only check of existing bundle rules; no collection is dropped or migrated.

The bell becomes the notification history interface, fetching five records per server page, deduplicating IDs, supporting read tracking and retaining session isolation. Shared select and searchable controls use a mature accessible primitive with preserved values, form names, disabled behavior and error associations. Sonner remains the only toast library, with brand styling and safe-area-aware bottom placement.

Implement and verify in milestones: shell/routes; consolidated pages and dashboard read contracts; Orders; feature retirement; notifications; shared controls; toasts; responsive polish; regression tests; release. Preserve all pre-existing untracked files. Commit only named intended files. Do not push unless the complete combined release passes checks and the remote remains compatible.
